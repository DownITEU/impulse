# shell

The GPUI UI crate: window root, page, trainer list, run, hotkey capture, tray, crash stop. Map and overlay have their own rules.

## Surface
- `init` (takes the data dir and the `Arc<Registry>`), `Assets`, `Root::new`, `Serve`: all `app` calls (`Root::new` takes `client::plugins::Plugins` and the remote panel's `Serve`, `None` in a build without it). Everything else is private.
- `Root`: the window root; draws `Page` with `cached`, the open map as a modal over it and LINK A MAP over both.
- `Page` (`page/`): the combined page, layout only: one `impl Page` in `page/mod.rs` makes the entities and lays out their views; `header` and `status_bar` are components.
- `Hero` (`page/hero.rs`): the open game's art, title, run button and actions; owns the sources menu (`close`).
- `Sidebar`, `GamePicker` (`library/`): the game list with its filter and the add-game dialog. The page gives the sidebar its `Marks` (favorite, live) as a function and makes the sidebar observe what it reads.
- `Library` (`library/`): the game list, the picked executables, the map links (`link`, `set_link`, `unlink`) and the open game; emits `LibraryEvent` (`Listed`, `Opened`, `Switched`, `Linked`). While the list is pending (start, reload) it shows `kept`, if any, until `scan`'s comes; each list shown emits `Listed`.
- `Trainers` (`trainer/`): the sheets by game, the `Hold`, `games.json`; emits `TrainerEvent` (`Installed`, `Rebound`, `Set`, and `Changed` for the rest that shows). `title` draws a game's name and meta.
- `CheatList` (`cheats/`): the open game's cheat list, drawn by the page and the HUD; its `Printed` projection, filter, menus, flash and `CollectionEditor` (emits `EditorClosed`; whoever draws `editor()` takes the focus back).
- `Runs` (`run/`): the run state, the session, the `Tracker`; `start`, `stop`, `set`, `step`, `press`, `apply`, `reset` (RESET), `toggle_collection`, `can_start`, `is_live`; emits `RunEvent` (`Starting`, `Failed`, `Live`, `Stopping`, `Ended`, `Pressed`). Views: `run_button`, `session_panel` (the hotkeys' scope comes in as a slot: `run` cannot name `bindings`), `run_note`.
- `Hotkeys` (`bindings/`: a `hotkeys` module would shadow the crate): `hotkeys.json`, the live run's hook, the capture and the question about a held chord (`Conflict`); `capture`, `cancel`, `rebind` (takes the window), `conflict_at`, `answer`, `dismiss`, `focus`, `set_enabled`, `set_game_only`. Views: `caps` (a cap outlined in WARN while its hotkey is `shared`, with its popover), `hotkeys_scope`, `HotkeySettings`.
- `Account` (`account.rs`): the first source's session, read by the header (NOT SIGNED IN wins over a kept name); `reload` asks again, as does opening a game while signed out. A reload after a failure that gets a session emits `SignedIn`: `Trainers` then asks again for the open game.
- `Folders` (`settings/`): every source's folders and the user's edits checked by their source (`scan`, `set`); emits `Shown(at)` when a row's field must show the source's path. `SettingsView` holds the fields.
- `Remote` (`remote/`): the remote panel's bridge: the server's life (the `remote` pref, once the disclaimer is accepted), `remote.json`, the pairing code and its QR, the game handles. It publishes the views on the owners' events (not their notifies: the run clock ticks), once per burst and only what changed, and applies a device's commands through the owners, refusing with a note; a burst's sets of one cheat go as the last. Covers come from the cache only. `RemoteView` is its dialog, opened by the header's phone button (absent in a build without the server).
- `Sources` (`sources.rs`): the registry's changes as `SourcesChanged` (the sources that came, went or were replaced), once per burst.
- `Plugins` (`plugins/`): the installed plugins' list (read on `Looked` and after each command), the pick waiting for approval, the last command's failure; `pick`, `approve`, `cancel`, `set_enabled`, `remove`, `set_value` through `client::plugins`, one at a time (a click while one runs is dropped). `approve` takes the digest of the card the user saw and does nothing for another pending pick. `PluginsView` draws the PLUGINS tab: the approval card, each plugin's switch, scopes, size, failure, REMOVE and settings (text and number fields kept on Enter or blur).
- `Resources` (`resources/`): sizes, clear, the media limit; clears the media (`app:` stores) itself and the rest through the registry; emits `Cleared(sources)`: the page reloads only when one of them plays (`Registry::plays`), so a plugin's answer cache stops no trainer; it measures again on a source change once a measurement was asked for. `ResourcesView` draws it in the RESOURCES tab.
- `Cues` (`sounds/`): a short tone (`sound`) when a live cheat's control changes, heard on `TrainerEvent::Set` and `RunEvent::Pressed` (a hotkey's or a click's), for the six cues the user left on (`Prefs::cues`: which are on and a WAV per cue to play instead; a slider and a number start off since a drag fires them per step). The only caller of `sound`, through one task off the UI thread (a WAV may sit on a share; only the newest waiting cue plays): `play` (LISTEN, on or off), `choose` (the file picker; `sound::is_clip` off the UI thread, a refusal is kept for its row), `clear`. `SoundsView` draws the SOUNDS tab and sends those commands. The user's file stays where it is (its path is the pref); a missing one plays the built-in tone.
- `Disclaimer` (`page/disclaimer.rs`): the first-launch notice about the account data, drawn by the page until `Prefs::disclaimer_seen`; the source names in its text come from `Registry::account_names` (`account_sources`), so no catalog text names a source. It is a `pledge`: nothing closes it but I AGREE (keeps the answer) and EXIT (`cx.quit()`: no run can be live yet, the tray icon goes on `on_app_quit`).
- `About` (`about/`): `Link` (the repository, Discord, a bug report that opens with the version, support, the author's mail) and `FEED` (the release list) are the one place that holds the project's addresses; `Link::open` goes through `cx.open_url`. The ABOUT tab (`about`), the status bar's quick icons and the log's FOUND A BUG? button use it. A new place to send the user is a `Link` variant, never a URL in a view. PLUGINS carries an ALPHA `badge` on its tab and a strip on top while plugins are alpha.
- `Updates` (`update/`): looking for a newer Impulse. A check at start (after 10 s) and every 6 h unless `no_update_check`, or CHECK NOW; the answer and its ETag are kept in `update.json` with the feed they came from (an answer of another feed is dropped), so a known update shows offline. The newest release of the chosen channel is fetched beside the executable at once; `offer`, `status` and what is `ready` follow the feed and `Prefs::update_channel` (a change of either drops what no longer applies). The swap runs in an app quit hook that holds a shared `Plan` (the entity may be gone by then): `restart` (RESTART NOW, refused while `Runs::is_active`) sets a flag, quits, and the swap starts the new executable. `Present(Mode)` is the one way to ask for a dialog: `UpdateNotice` (`page/update_notice.rs`) shows it behind the disclaimer and SignedOut and emits `Opened`, when the page closes Settings. Unasked it shows the notes of a build just installed (`due`: `New`, from the exe's own `CHANGELOG.md`) or an offer not yet shown, once each (`acknowledge`). With `no_update_check` on, nothing offered shows unasked (`announces`: no dialog, no chip, no fetch from a cached offer) until a CHECK NOW. SKIP THIS VERSION (`skip`, kept in `update.json`) drops the newest release and every older one from the offer (`Status::Skipped`); a newer one is offered as ever and CHECK NOW lifts the skip. `UpdatePanel` is the ABOUT tab's rows, `chip` the status bar's; the bar's version opens the changelog.
- `SignedOut` (`page/signed_out.rs`): the notice that the account source could not sign in (no app, no session, no connection: `SignIn::Failed`), shown once the disclaimer is gone. A `dialog` the user may close; TRY AGAIN is `Account::reload`.

## Rules
- Media loads through `ui::art`, as GPUI's images do: an `http://` or `https://` URL from the CDN, a source's own URL (any other scheme, `<source>:...`) through `Registry::download`, both under the same disk cache. `NotFound` counts as a 404 and `Refused` as a 403 for the absent rules; any other failure is an error, asked again. `init` gives GPUI's http client the registry and sets the `Router` global; work off the UI thread reads it first and moves the `Arc<Registry>` in.
- Colors and fonts come only from `ui/theme.rs`; a new token goes there. The user's accent and the UI font are the `Look` global: read them with `accent(cx)` and `ui_font(cx)`, never pass them along. The font follows the language (Exo 2 for a Cyrillic one, added to the font system when first needed); fonts are static OFL files in `assets/fonts` with their `OFL-*.txt`.
- A caption is a catalog message (`i18n.md`): `t(cx, key::X)`, never a literal (`checks` finds one). A kept text follows a language change: inputs come from `input` or `filter_input` with a `Key`, or keep `relabel`'s subscription; whoever stores a made text observes `Texts`.
- Use the `ui/widgets.rs` primitives (and `ui/dialog.rs`: `dialog`, `pledge` for one that only its buttons end, `message` for a text over buttons; `ui/dropdown.rs`: `dropdown` over its `trigger`) (`button`, `icon_button` and `tinted_icon_button`, `badge`, `switch` (a `toggle` that is the click target), `toggle`, `choice`, `notice`, `tip`, `keycap`, `mono`, `tracked`, `input`); never a raw `div` styled as one.
- Logic without GPUI goes to `client` (its rules: `client.md`): app files are its `Stored<T>`, opened from `Paths` by the slice that owns them.
- `Settings` (`settings/`) owns the prefs: read them with `settings.read(cx).prefs()`, change them with `Settings::edit`. It sets `Look`, `Texts` (the language, and again with the registry's catalogs on `SourcesChanged`) and GPUI's reduce motion; whoever reacts to a pref observes it.
- Sources that change while the app runs reach `Settings`, `Titles`, `Maps` and `Resources` as `SourcesChanged`. A new `Texts` in the same language reloads nothing: whoever reloads on a language change compares `content_locale` first.
- `Library` owns the open game: open one with `Library::open`, react to `LibraryEvent`. A view holds the open game as an `Arc<Game>` while it draws.
- `Trainers` owns the sheets and the profiles: read them through it, change them with its commands. It never knows the run: a run holds its game's copy with `hold`.
- Sources come only through the `Arc<Registry>` the entities hold. Its streams: the catalog in `Library`, trainers in `Trainers`, sign-in in `Account`. `Cached(Some)` shows at once; `Fresh(Err)` never empties a cached copy (it marks it `stale`); a library error shows only with no copy. A failure shows as `why` (the source's words or its kind's, and where to fix a missing setting), never its chain.
- `Trainers` loads the open game's trainer only: nothing is downloaded for a game the user did not open (the API cuts a client off after about ten trainer requests).
- Sources are asked in `content_locale(cx)`, the language's tag. A switch reloads the open game's trainer (the maps: `shell-map.md`); every other copy asks again at its next open (`Shelf::outdate`), which reads the disk unless that copy is in another locale. A load that ends after a switch outdates its own game only.
- A starting or live run carries its game's `Hold`: a newer copy waits until it drops, then shows with the pins, folds and hotkeys set meanwhile. The release lands on the next executor turn.
- `Runs` owns the run: views read it and send its commands; whoever reacts to a run subscribes to `RunEvent` (`crash::watch`, `Layer`, `Hotkeys`, `Maps`, `TrayIcon`, `Remote`). It stops a run whose game left the list.
- `Printed` is made on `Opened` and `Installed` of the open game and on a language change, re-capped (caps and `shared`) on `Rebound`; a number field follows `Set`. The cheat list reads the sheet in place through `Trainers`.
- One run at a time: `Runs::start` refuses while `is_active`. `Stopping` lasts until `Session::stop` returns.
- A cheat value goes one way: `Runs::set`, `step` or `apply` change the live sheet through `Trainers` and send it; they do nothing without a live run. A run's time and mods are kept once (`closed` flag), on end, STOP, quit and release.
- Every live session is followed by `crash::watch`: a UI-thread panic stops it before the process ends.
- `TrayIcon` (`systray.rs`) owns the icon, its menu (it observes `Runs`, `Library`, `Layer`), the close button and quitting. Quit: `quit` drops the tray icon first (quitting skips drops), stops a live trainer, then quits on `RunEvent::Ended` or after 5 s. Closing the window follows `quit_on_close`: quit, else hide in the tray.
- `Hotkeys` arms the live run's hook on `RunEvent`s and lays the user's choices over each copy on `Installed`. It never names the overlay: the overlay's keys reach it as the `reserved` test it is built with.
- A capture's outcome goes to its asker (`capture` returns a receiver), who applies it: the cheat list with `Hotkeys::rebind`, the overlay tab with the layer's setters. A capture hides keys from every app; it ends on its outcome, a click outside the cap, the window going inactive, another game opening, a copy of its game's trainer showing, the overlay opening or the run's hook arming.
- A chord another hotkey holds is never refused silently: `rebind` turns it into a `Conflict` and the slot keeps its hotkey. The popover over the cap answers it (KEEP BOTH, REBIND, Escape or a press beside it; the hook is already gone, so Escape comes as a GPUI action). The question takes `Hotkeys::focus` and gives the old focus back when it ends by an answer, a dismissal or the window going inactive. It also ends when another game opens or a copy of its game's trainer shows, with no window at hand to give the focus back in. The cap's press-outside runs deferred (an answer's button lies outside the cap), and an answer's press prevents the default so the box does not take the focus again. A press that ends as the window goes inactive asks nothing.
- A hook handler only forwards to a channel; no GPUI call, no lock.
- Every header control calls `occlude()`: GPUI picks the window control area by the first hitbox under the cursor.
- What repaints often is its own entity (`LogView`, which also owns whether it is open; `ResourcesView`; the map parts); never `cx.notify()` the page from a per-frame or per-record path.

## Traps
- `Page` is drawn cached: it re-renders only when it notifies, so an entity it reads must be observed. The session clock notifies it once a second while a run is live. A changed global reaches cached views only through `cx.refresh_windows()`.
- The cheat list's menu, flash and editor hold an index: `CheatList::drop_state` whenever the trainer or game changes. A capture targets a cheat by id, not index: a newer list may arrive meanwhile.
- `reload` (caches cleared) stops the run first: it keeps what the run leaves on, from trainers about to go.
- `tracked` lays out one element per grapheme cluster: short captions only. `keycap` and `fitted` cut text only inside a parent with `min_w_0`.

## New code
`Page` only makes entities and lays out views. New state goes into its slice's entity with events; a view renders and sends commands only; a reaction across slices subscribes to an event, never a hand-called sync. An upward need comes as a slot or a function given at construction.
