# i18n

Texts the user reads, in their language: the `i18n` crate, the catalogs and how code names a message.

## Surface
- `Language` (`tag`, `name`), `LANGUAGES` (what we ship), `Language::system`, `Language::find`.
- `Catalog::new(language, pseudo, domains)`, `text(domain, key, args)`; `Key`, `Arg`, `Files`.
- In `shell`: `ui::text::Texts`, a global set by `Settings`, and `t(cx, key)`; `ui::key`, a const per message of `crates/shell/locales/en.ftl`.

## Rules
- A domain is a crate's `locales/<tag>.ftl`: `app` is `shell`'s; a source's is named by its `SourceId`.
- Code names a message only through a `Key("id")` const of its crate. `checks` holds every key to an English message, every English message to a key, every other language to the English set, and parses every file.
- A text is written in its final case: no `to_uppercase` on our own text. Plurals and units are Fluent selectors, never `if n == 1`.
- A message without arguments is made once per language (`t`); one with arguments when its data changes, never per frame.
- A missing message falls back to English; its key shows only when English lacks it too.
- `IMPULSE_LOCALE=pseudo` in a debug build accents and stretches every message's own text: a cut or an English literal shows.
- `i18n` knows no GPUI and no crate of ours; Fluent types stay inside it.

## Traps
- Fluent's isolation marks are off: GPUI draws them as boxes.
- `gpui-component` keeps its own texts (input menus) in `rust-i18n`; `Settings` sets its locale too. It has no French.
